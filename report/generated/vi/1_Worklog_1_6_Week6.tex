\vspace{0.5em}\noindent\textbf{Triển khai kỹ
thuật}\par

The CI/CD path uses GitHub Actions OIDC to assume the AWS deployment
role instead of storing long-lived AWS access keys. ECR image URIs are
based on AWS account, region, repository name, and immutable Git SHA
tags.

\textbf{Mô tả sơ bộ.} GitHub Actions nhận token OIDC và đảm nhận
deployment role có phạm vi giới hạn. Role này cho phép đẩy image backend
và chat gắn thẻ SHA lên ECR, đồng thời cho phép script triển khai cập
nhật workload EKS mà không cần lưu AWS credential dài hạn.

The source repository includes deployment scripts for both EKS
application deployment and frontend deployment. I keep sensitive runtime
values such as \texttt{DATABASE\_\allowbreak{}URL}, \texttt{REDIS\_\allowbreak{}URL}, and
\texttt{SECRET\_\allowbreak{}KEY} in environment variables or Kubernetes Secrets, not
in published documentation.

\vspace{0.5em}\noindent\textbf{Bài học rút ra}\par

AWS CI/CD work depends on both IAM and runtime evidence. A workflow file
can be correct structurally, but I only mark authentication, image push,
or cluster access as verified when the corresponding AWS/Actions log is
available.
