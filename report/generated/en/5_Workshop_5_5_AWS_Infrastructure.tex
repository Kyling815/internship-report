\vspace{0.5em}\noindent\textbf{AWS Infrastructure}\par

\vspace{0.5em}\noindent\textbf{Objective}\par

Document the AWS infrastructure required by the production deployment
and provide safe verification commands for each major resource.

\vspace{0.5em}\noindent\textbf{Scope}\par

This chapter documents implemented resources where evidence is
available, identifies fields that still require exported AWS CLI
evidence, and lists optional hardening separately.

\vspace{0.5em}\noindent\textbf{Architecture context}\par

The infrastructure supports a hybrid edge and container architecture:

\begin{itemize}
\tightlist
\item
  CloudFront and S3 serve the frontend.
\item
  The ALB routes dynamic traffic to EKS.
\item
  EKS runs long-running application workloads.
\item
  Managed databases, messaging, object storage, Lambda, SES, and
  SageMaker provide platform services.
\item
  GitHub Actions deploys through OIDC, not through long-lived AWS access
  keys.
\end{itemize}

\vspace{0.5em}\noindent\textbf{Network foundation}\par

The production EKS cluster requires a VPC with public and private
subnets:

\begin{itemize}
\tightlist
\item
  Public subnets host internet-facing load balancer resources and NAT
  Gateway resources.
\item
  Private subnets host EKS nodes and internal managed service access.
\item
  An Internet Gateway supports public ingress and NAT egress.
\item
  A NAT Gateway gives private nodes outbound access for image pulls, AWS
  APIs, package downloads, and control-plane integration.
\end{itemize}

Evidence required:

\begin{itemize}
\tightlist
\item
  VPC ID, except the troubleshooting incident confirms
  \texttt{vpc-\allowbreak{}0cfee519122ae18b4} was used by the AWS Load Balancer
  Controller.
\item
  Public subnet IDs.
\item
  Private subnet IDs.
\item
  Route table IDs.
\item
  Security group IDs and rules.
\item
  NAT Gateway ID and Elastic IP allocation ID.
\end{itemize}
