\vspace{0.5em}\noindent\textbf{Objective}\par

Provide a safe, dependency-aware cleanup sequence for the AWS production
environment after testing or demonstration is complete.

\vspace{0.5em}\noindent\textbf{Warning}\par

The commands in this chapter are destructive. Do not run them unless the
project owner, AWS account owner, and team have approved cleanup. Export
required evidence, logs, test results, cost reports, and final
screenshots before deleting resources.

This chapter is documentation only. No cleanup commands were executed as
part of preparing this report.

\vspace{0.5em}\noindent\textbf{Architecture context}\par

Cleanup must follow dependency order. Deleting shared networking or IAM
first can leave load balancers, ENIs, node groups, endpoints, queues,
buckets, or log groups stuck. The safest approach is to stop producers,
stop consumers, delete high-cost compute, then remove networking and IAM
last.

\vspace{0.5em}\noindent\textbf{Pre-cleanup checklist}\par

\begin{itemize}
\tightlist
\item[$\square$]
  Confirm the environment is no longer needed.
\item[$\square$]
  Export CloudFront, ALB, EKS, RDS, Redis, DynamoDB, SQS, Lambda,
  SageMaker, and S3 evidence.
\item[$\square$]
  Export AWS Cost Explorer or Pricing Calculator evidence.
\item[$\square$]
  Export Lambda logs for the final smoke test.
\item[$\square$]
  Export any required S3 event archive objects.
\item[$\square$]
  Confirm no production users depend on the deployment.
\item[$\square$]
  Confirm backups or snapshots are either retained or intentionally
  deleted.
\item[$\square$]
  Confirm the active AWS account is the intended project account.
\item[$\square$]
  Confirm the active region is \texttt{ap-\allowbreak{}southeast-\allowbreak{}1}.
\end{itemize}

\vspace{0.5em}\noindent\textbf{Outcome}\par

Cleanup is complete only when high-cost services, queues, buckets,
databases, load balancers, endpoints, IAM roles, and VPC resources are
removed or intentionally retained with written approval.
