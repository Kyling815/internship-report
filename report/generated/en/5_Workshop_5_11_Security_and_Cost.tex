\vspace{0.5em}\noindent\textbf{Objective}\par

Document the security controls and cost-estimation approach for the
production AWS deployment.

\vspace{0.5em}\noindent\textbf{Architecture context}\par

The platform processes user accounts, CVs, job applications, chat
messages, AI analysis, event notifications, and email. Security controls
must protect identity, secrets, private data, deployment roles, storage,
network paths, and event processing. Cost controls must pay special
attention to always-on resources such as EKS, NAT Gateway, RDS, Redis,
ALB, and SageMaker.

\vspace{0.5em}\noindent\textbf{Authentication and
authorization}\par

The backend uses JWT-based authentication and role-aware routes for
candidate and HR workflows. The frontend stores the session under the
\texttt{internship\_\allowbreak{}tracker\_\allowbreak{}} prefix and clears local/session storage
on session expiration. Protected frontend routes redirect users
according to role.

Security expectations:

\begin{itemize}
\tightlist
\item
  Passwords must be hashed.
\item
  JWT secret must remain in secrets management, not in source code.
\item
  Candidate and HR routes must enforce ownership and role checks on the
  backend.
\item
  AI scores should assist review but not become the only hiring
  decision.
\end{itemize}

\vspace{0.5em}\noindent\textbf{Evidence hygiene}\par

Before I use any AWS evidence image or log in the documentation, I
redact AWS account IDs, access keys, secret keys, database passwords,
connection strings, Kubernetes Secret values, GitHub tokens, presigned
URLs, and logs containing credentials.

My evidence scan did not find obvious access keys or GitHub tokens, but
\texttt{02-\allowbreak{}eks/\allowbreak{}pod-\allowbreak{}logs-\allowbreak{}tail.\allowbreak{}txt} contains a Redis connection URL with
an embedded credential from chat-service startup logs. I do not upload
or paste that raw file. I use only a summary or replace the whole value
with
\texttt{\textless{}REDACTED\_\allowbreak{}REDIS\_\allowbreak{}CONNECTION\_\allowbreak{}STRING\textgreater{}}.

\vspace{0.5em}\noindent\textbf{Largest cost drivers}\par

The highest-risk future cost areas are:

\begin{itemize}
\tightlist
\item
  SageMaker real-time endpoint uptime, especially if the selected
  endpoint instance is GPU-backed.
\item
  EKS control plane and EC2 worker nodes running continuously.
\item
  RDS and Redis always-on managed capacity.
\item
  ALB hourly and LCU usage.
\item
  CloudFront and data transfer when traffic grows.
\item
  CloudWatch log ingestion and retention if verbose logs are kept.
\end{itemize}

The Week 8 evidence shows that cost is no longer near zero. SageMaker,
RDS, VPC/NAT-related networking, EC2 worker nodes, and EKS should be
treated as active cost drivers. SageMaker should be stopped or deleted
when demos finish if real-time inference is not required.
