variables, CloudFront routing, queue naming, DynamoDB expressions, IAM,
and AI dependency readiness.

\vspace{0.5em}\noindent\textbf{Detailed incident notes}\par

\vspace{0.5em}\noindent\textbf{NAT Gateway blackhole}\par

Private EKS worker nodes need outbound connectivity to reach AWS APIs
and pull images. When the private subnet default route points to a
deleted NAT Gateway, the route state becomes \texttt{blackhole}. Nodes
fail to join or remain unhealthy.

Useful commands:

\begin{Shaded}
\begin{Highlighting}[]
\ExtensionTok{aws}\NormalTok{ ec2 describe{-}route{-}tables }\AttributeTok{{-}{-}region}\NormalTok{ ap{-}southeast{-}1}
\ExtensionTok{aws}\NormalTok{ ec2 describe{-}nat{-}gateways }\AttributeTok{{-}{-}region}\NormalTok{ ap{-}southeast{-}1}
\ExtensionTok{aws}\NormalTok{ eks describe{-}nodegroup }\AttributeTok{{-}{-}cluster{-}name}\NormalTok{ internship{-}prod }\AttributeTok{{-}{-}nodegroup{-}name} \OperatorTok{\textless{}}\NormalTok{NODEGROUP\_NAME}\OperatorTok{\textgreater{}}\NormalTok{ {-}{-}region ap{-}southeast{-}1}
\ExtensionTok{kubectl}\NormalTok{ get nodes }\AttributeTok{{-}o}\NormalTok{ wide}
\end{Highlighting}
\end{Shaded}

\vspace{0.5em}\noindent\textbf{CloudFront routing
correction}\par

Correct current design:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{CloudFront default *        {-}\textgreater{} S3 frontend origin}
\NormalTok{CloudFront /api/*           {-}\textgreater{} ALB origin {-}\textgreater{} backend}
\NormalTok{CloudFront /chat/*          {-}\textgreater{} ALB origin {-}\textgreater{} chat{-}service}
\NormalTok{CloudFront /socket.io/*     {-}\textgreater{} ALB origin {-}\textgreater{} chat{-}service}
\end{Highlighting}
\end{Shaded}

Incorrect design to avoid:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{S3 behind ALB}
\NormalTok{frontend running in EKS}
\end{Highlighting}
\end{Shaded}

\vspace{0.5em}\noindent\textbf{Lambda DynamoDB reserved
word}\par

The failing expression used \texttt{result} directly. The fixed pattern
uses an expression attribute name:

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{\{}
  \DataTypeTok{"UpdateExpression"}\FunctionTok{:} \StringTok{"SET \#result = :result"}\FunctionTok{,}
  \DataTypeTok{"ExpressionAttributeNames"}\FunctionTok{:} \FunctionTok{\{}
    \DataTypeTok{"\#result"}\FunctionTok{:} \StringTok{"result"}
  \FunctionTok{\}}
\FunctionTok{\}}
\end{Highlighting}
\end{Shaded}

\vspace{0.5em}\noindent\textbf{General diagnostic
workflow}\par

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Confirm AWS account and region.
\item
  Confirm kube context and namespace.
\item
  Check CloudFront behavior and ALB Ingress status.
\item
  Check Kubernetes deployment rollouts and pod events.
\item
  Check application logs.
\item
  Check managed service health.
\item
  Check IAM AccessDenied errors and CloudTrail if available.
\item
  Check queue, Lambda, DLQ, and dedupe state for async failures.
\item
  Record exact timestamps, command outputs, and final resolution.
\end{enumerate}

\tightlist

\item
  command evidence captured
\item
  fix applied
\item
  verification result recorded
\item

\vspace{0.5em}\noindent\textbf{Outcome}\par

The troubleshooting record turns deployment failures into reusable
operational knowledge and helps future maintainers diagnose networking,
IAM, CloudFront, SQS, Lambda, and SageMaker issues faster.
